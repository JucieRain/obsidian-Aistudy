# 横纵分析法

> 数字生命卡兹克提出的深度研究框架，半小时建立陌生领域的完整认知

## 核心定义

横纵分析法包含两条轴：

### 纵向（Diachronic / Longitudinal）

沿着时间线，还原研究对象从诞生到现在的发展全貌：
- 它怎么来的？谁做的？
- 中间经历了什么？
- 为什么在某个节点突然爆发或掉头？

**纵向追时间深度**：理清历史与因果。

### 横向（Synchronic / Cross-sectional）

在当下时间点，把它跟同赛道的其他东西放在一起比：
- 它跟竞品有什么不同？
- 用户为什么选它不选别的？
- 它在整个赛道里是什么位置？

**横向追同期广度**：理清位置和差异。

### 交汇

两条轴交叉起来看：
- 纵向告诉你它是怎么走到今天的
- 横向告诉你它今天站在哪
- 单独看任何一条轴都看不到的东西就浮现出来

> "纵向追时间深度，横向追同期广度，最后交汇出判断。"

## 学术渊源

### 索绪尔：历时分析 + 共时分析

语言学经典研究视角：
- **历时分析**：时间维度，看演变轨迹
- **共时分析**：当下维度，看系统位置

### 社会科学：纵向研究 + 横截面研究

- **纵向研究**：追踪一个对象的变化轨迹
- **横截面研究**：某时间点观察截面状态并横向对比

横纵分析法把这些学术视角抽离，结合商业和竞争战略分析思路，形成通用研究框架。

## 适用范围

| 研究对象类型 | 示例 |
|-------------|------|
| **产品/工具** | Hermes Agent、Cursor、Claude Code |
| **公司/组织** | Anthropic、字节跳动、OpenAI |
| **技术概念** | MCP协议、RAG、Agent框架 |
| **人物** | 行业关键人物的职业轨迹 |

Prompt会根据研究对象类型，自动调整纵向和横向分析的侧重点。

## 研究框架

### 纵向分析要求

1. **起源追溯**：诞生的背景、技术/理念/需求、创始团队、当时行业环境
2. **诞生节点**：首次发布时间、最初形态和定位
3. **演进历程**：关键节点时间线（版本更新、融资、战略转型、技术变化、用户里程碑、重大事件）
4. **决策逻辑**：为什么选A不选B？当时面对的约束条件是什么？
5. **叙事要求**：用故事串联，不是干巴巴年表

### 横向分析要求

**先判断竞品情况**：

| 场景 | 处理方式 |
|-----|---------|
| **无直接竞品** | 分析：为什么没有？未来可能从哪冒出竞争者？替代方案是什么？ |
| **少量竞品(1-2)** | 逐一深入对比 |
| **竞品充分(3+)** | 选3-5代表对比，其余简要提及 |

**对比维度**（灵活调整）：
- 技术路线/方法论差异
- 产品形态/商业模式差异
- 目标用户/适用场景差异
- 核心优势与明显短板
- 定价策略/资源投入/规模体量
- 用户口碑与社区评价
- 生态位分析
- 趋势判断

## 输出特点

### 篇幅要求

| 部分 | 字数 |
|-----|------|
| **纵向分析** | 6000-15000字（报告主体） |
| **横向分析** | 3000-10000字 |
| **横纵交汇总结** | 1500-3000字 |
| **全文总计** | 10000-30000字 |

### 写作风格

- **可读性优先**：像深度报道，有节奏感画面感
- **叙事驱动**：不是罗列，有起承转合
- **观点有事实支撑**：先摆事实再给判断，推测要标注
- **用人话写**：避免"赋能""抓手"等套话
- **对比有温度**：讲清楚每个竞品"活成了什么样"

## 方法局限

- 能快速建立认知框架，但替代不了亲自深入研究
- AI可能幻觉，拿到报告后对疑问点再深挖
- 模型质量影响输出效果，推荐用Deep Research功能（10分钟以上任务）

**正确用法**：报告作为研究起点，建立地图后再深入探索。

## 实战案例

研究Harness（Claude深度研究）：
- 纵向：历史清晰，诞生时间、爆发节点、关键决策
- 横向：对比Prompt Engineering、Context Engineering、Agent Engineering
- 13分钟产出1万字报告
