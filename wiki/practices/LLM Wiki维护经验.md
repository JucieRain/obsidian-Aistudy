# LLM Wiki维护经验

> 养 Wiki 和养花一样，得浇水、除草、定期检查根有没有烂。

## 三周实践发现的问题

实践 Karpathy LLM Wiki 方法三周后，wiki 目录多出六十几个页面，发现三个问题：

| 毛病 | 表现 | 根因 |
|-----|------|------|
| **漂移** | Wiki页面和原文不一致 | AI摘要是有损压缩，每次更新都可能引入偏差 |
| **孤岛** | 有些页面没人引用 | 没有主动关联机制 |
| **找不到** | AI忘记早期内容 | Wiki超过50页，index.md太长，效率下降 |

## 解法一：给Wiki加溯源

每个关键事实标注来源位置（行号）：

```
该公司营收"10.3 亿元"。
— raw/annual-report.md, L128
```

好处：
- 一秒钟跳到原文验证
- AI可以做自动对比检查

AGENTS.md加规则：
```
数字、百分比、具体结论，必须原文引用并标注来源行号。
不要用 AI 的话重述数字。
```

## 解法二：定期体检

### 常规体检（每周）

检查五件事：
| 项目 | 说明 |
|-----|------|
| 矛盾 | 同一事实不同页面说法不同 |
| 过时 | raw素材更新但wiki没更新 |
| 孤岛 | 无入链的页面 |
| 断链 | 引用不存在页面 |
| 漂移 | 随机抽查摘要和原文对比 |

### 深度体检（每月）

```bash
深度体检：随机抽 5 个摘要页面，逐条对比原始文档
```

AI 会读摘要、读原文、逐条比对、报告偏差、然后修复。

## 解法三：给Wiki加搜索

Wiki超过50页后需要搜索工具，否则 AI "找不着"早期知识。

推荐工具：
- **qmd**：本地Markdown搜索引擎，BM25+向量混合搜索，有CLI和MCP两种模式
- 简单grep脚本也够用：`grep -ril "$1" ~/my-wiki/wiki/`

## 评论区精华

@gulliveruk 的观点：

> 确定范围应该是确定性的，推理应该是概率性的。

把"找"和"想"分开：
- 找：用确定性工具（标签、元数据、搜索）
- 想：AI只在精确筛选范围内做推理

## 关键认知

- Human owns verification（人拥有验证权）
- AI是园丁，可以浇水除草
- 但种什么花、留哪棵——人说了算
