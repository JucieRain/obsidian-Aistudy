我们来写一下这段时间整体的AI待办任务，主要是五一期间的：

1. 项目管理系统
   核心聚焦于项目管理系统如何做成skill，并扩展到整个模块进行使用。这是第一个大事。
	1. 重新进一步简化“人力能力模型”与“匹配”的对照表
	2. 优化整个数据录入环节的人工意图理解，这部分的逻辑需要定义得更清晰一些（注：此项非当前最高优先级）
	3. 落实一个子任务：研究如何通过 WeLink CLI 自动进行信息接收
	   (a) 方案相当于挂载一个 Agent 聊天工具
	   (b) 具体实现路径需要进一步调研
2. 知识库管理
   研究当前最核心的 TSE 测试工作集该如何处理。
    几个需要研究的子任务：
	1. 工作区文件结构与 AI 引导
	   需要明确该工作区的整个文件结构如何创建，并为 AI 提供一份简易说明及配套的工作流。
	
	2. 工作流核心模块
	   (a) 测试用例输出：目前设想以 Markdown 为主。核心任务是将过往用例全部 Markdown 化，并利用双向链接进行关联。
	   (b) 测试数据汇总：实现测试数据与对应用例的自动化回溯与连接。
	   (c) 整体测试指导：建立一个大型数据库，将具体用例的测试指导与历史预测结果、正式测试结果进行关联。
	
	3. 核心技术痛点
	   (a) 格式无损转换：解决 Markdown 与 Word 之间格式化转换的痛点，确保转换不失真。
	   (b) 组网图兼容性：研究组网图的画法，使 Markdown 能识别并将其转化为图片存入 Word；同时支持 Word 转回 Markdown 时，能将图片直接还原为组网图形式。
	   (c) 知识库承载方案：确定整套知识库的底层架构，研究是基于特定数据库、表格链接还是其他处理方式，这是目前需要解决的另一大难点。
3.实验室物料管理
   结合 AI 梳理实验室整体物料的全生命周期管理，并列出一个详细的计划。
   目前物料管理存在几个核心痛点：

		1. 账务管理不细致：整体账目尚未完全梳理清晰，且物料的存放位置缺乏科学的分类。
		2. 管理难度大：由于项目多、物料种类繁杂，实际负责管理的同学对部分物料缺乏认知，导致分类、管理和存放无从下手。
		3. 特殊物料丢失风险：很多特殊物料未做好标记，或存放位置不为人知。在清理过程中，由于缺乏专门的核对，导致关键的特殊物料被混放甚至丢失。
		4. 积压物料待处理：现有的存量物料急需集中清理，但目前尚未投入足够的时间进行处理。
		5. 存放空间不足：物料存放空间受限。节前的讨论方案是：撤掉实验室内的三个悍马桌和一个隔音舱，将其改造为货架，用于设备的放置。
		6. 周转效率与成本问题：物料周转频率较高，如何保障周转过程高效运转、实现实时跟踪，并减少人工投入的成本和精力，是目前亟待解决的痛点。
